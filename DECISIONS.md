# Design decisions

This file records choices that affect the document model, file compatibility, or core editing behavior. Revisit them deliberately; do not treat implementation details or unresolved questions as settled decisions.

## Document model and connectivity

- Wrapped text notes are independent `TextNote` document objects with separate IDs, top-left positions, plain multiline text and wrapping widths; they have no electrical topology or library symbol/reference. V9 persists notes, while height remains derived. A single note is edited in Properties; selected side handles resize its width, with automatic height. Notes share selection, clipboard and snapshot undo/redo, and stay upright when group anchors transform. SVG includes wrapped text without editing boxes. See the [text-note design](docs/design/text-notes.md).

- In Draw Wire mode, a left-button double-click completes the active draft at the resolved connection point or, in empty space, at a snapped free endpoint. `addWireToPoint` materializes a bare node and any start-branch split atomically; invalid geometry leaves the draft and document unchanged. The editor remains in Draw Wire after completion, and a double-click whose first click already completed the wire never starts another draft. Free ends use the existing node identity and JSON representation, are reconnectable through normal wire gestures, and have no junction dot unless enough legs meet there.

- The document model is independent of Qt rendering items and input handling. `Document` is the source of truth; the scene and view render it and route user edits through its API.
- Electrical connectivity comes from endpoint identity, never coordinate coincidence. Endpoints refer to component terminals or explicit document nodes. Nets and junction positions are derived; crossings do not connect unless the user explicitly creates a branch.
- Placing a new component (canvas click or palette drop) connects each terminal that exactly touches an unambiguous wire after placement snapping. `Document::placeComponent` splits a wire interior/corner into two routes meeting at the new terminal identity, or replaces a bare junction node with that terminal across all incident routes. Multiple terminals can attach along the same original wire. Placement and connection are one atomic, undoable edit, with no format change; `addComponent` remains the low-level unconnected creation API. Moves, loads and clipboard paste do not infer new connections from coordinates. Separate crossing sites and points already owned by another component terminal remain unconnected with a placement status message. Deleting the placed component preserves its incident wire legs by detaching terminal endpoints to bare nodes.
- Junction dots represent three or more incident legs: bare nodes need three wire ends; component terminals contribute their symbol lead and therefore show a dot with two or more wire ends. A single wire ending on a terminal has no junction dot. Dots remain derived from explicit endpoint identities.
- A committed wire has resolved endpoints and an orthogonal route with no collinear reversal. A diagonal pointer move gets a deterministic horizontal-first corner. Grid alignment is an editing convenience, not a validity requirement for saved routes.
- Component positions, symbol geometry, and terminal coordinates use the same world/scene units. Grid spacing affects snapping and grid-line spacing; it does not scale symbols. Terminals are not required to land on grid intersections.
- Component movement updates attached route endpoints while preserving endpoint identities and validating candidate routes before commit.
- Removing a component preserves incident wire IDs and route coordinates. Each used terminal is replaced by one bare node at its position, so wires sharing that terminal stay joined; different terminals and coincident unrelated endpoints stay separate. Delete and Cut remove only explicitly selected wires. Batch deletion stages selected-wire removal before component detachment and rejects atomically if node identities cannot be allocated. Unreferenced nodes are cleaned up by wire deletion.
- Persistent net IDs and separately serialized junction lists are not part of the version 1 format.

## File format

- File > Open Recent is application history, stored in `QSettings` under `files/recentFiles`, not in the document or undo stack. It keeps at most ten successful opens/saves, newest first, deduplicated by canonical absolute path (absolute clean path when unavailable; case-insensitive on Windows). Recent entries call the normal document-open transaction, including unsaved-change and symbol-review handling. Failed/cancelled opens and saves do not change history. Missing files remain available for retry; Clear Recent Files removes only the settings history. SVG exports and symbol imports do not enter this schematic-file list.

- Complete-schematic SVG export uses an application-layer Qt SVG generator and a pristine scene built from a committed document snapshot. It shares canvas geometry and visible property layout, preserves vector artwork and editable text, uses transparent item bounds with a 10-unit margin, and excludes grid and all interactive overlays. One shared File > SVG Export action supplies Ctrl+E and the File-toolbar icon. Output is atomically written through `QSaveFile`; exporting changes no schematic filename, document/history or clean state. Qt SVG is required by the app/export targets, while `schematiccore` remains Core-only. See the [SVG export design](docs/design/svg-export.md).

- Project documents use versioned JSON. Version 1 stores grid spacing, components, explicit nodes, wire vertices, and endpoint references. Nets and junctions are derived.
- On load, wire endpoint coordinates are recalculated from terminal or node identity. A stale serialized endpoint is a warning; invalid topology or route geometry rejects the whole document. The loader rejects collinear reversals rather than normalizing saved geometry.
- Symbol IDs (the `kind` property of a saved component) are part of the serialization contract. Terminal geometry also affects loading because endpoint positions are derived from the current symbol definitions, and saved wires refer to terminals by index. A released symbol's terminal count, order, names, and positions must therefore never change under the same ID; any terminal-interface change gets a new ID. Glyph artwork and presentation metadata may change under the same ID because they do not alter connectivity. A document that uses an unknown symbol ID is rejected, with an error that names the component and the ID.
- Milestone 2 adds format version 2 for horizontal mirroring; v3 embeds symbol definitions; v4 preserves black/white primitive fill colour. V5 adds ordered instance properties and visibility. V6 adds optional canvas-axis property-block offsets. The loader accepts v1-v13; v1 components are unmirrored and may not contain a `mirrored` property. V2 and later require a boolean one per component. V7 embeds layout controls and reachable alternative definitions. Writers emit v13, so saving an earlier document upgrades it. V8 adds property-block justification; v9 adds independent text notes. Older builds reject newer format versions rather than silently discarding layout metadata or notes. V1–v5 load with automatic block placement.
- For legacy v1–v4 documents, missing, empty, and whitespace-only references are generated from per-kind prefixes with a warning. Generation avoids collisions deterministically. Duplicate non-empty references are load errors that name both components; they are not silently renamed. References are trimmed and compared case-sensitively. Loaded values are trimmed as well.

## Symbols and labels

- In Select mode, a left-button double-click on a terminal or existing document node enters Draw Wire and begins a draft from that identity. Connection-point picking takes priority over component-body double-click editing. Starting/cancelling the draft changes no document/history state; completion uses the normal atomic wire edit. Plain wire segments do not trigger this shortcut, and component-body double-click editing remains available.

- Mouse-wheel behaviour is an application preference under General, persisted as `general/cadStyleMouseWheel` and enabled by default. CAD style uses wheel zoom and Ctrl+wheel vertical scrolling; disabling it restores wheel scrolling and Ctrl+wheel zoom. OK saves and applies the setting to the canvas immediately, Cancel/Escape/window close discard edits, and startup restores it. It does not alter the document, undo history or file format.

- Symbol fill is monochrome: no fill, opaque white, or opaque black. The existing optional `filled` flag and per-kind defaults remain; `fillColor` defaults to White and is serialized only for Black. Legacy stored filled shapes remain white. SVG imports follow explicit/inherited none/white/black and SVG's default black; exports preserve the effective colour. Canvas, palette, and import previews share brush selection. Terminal signatures and stroke styling are unchanged. See the approved [black-fill design](docs/design/black-symbol-fills.md).

- Rotation is limited to 0, 90, 180, and 270 degrees. Horizontal mirroring is out of scope for milestone 1 and in scope for milestone 2 (format v2); arbitrary-angle rotation remains out of scope. The toolbar now supports canvas-axis horizontal and vertical flips using the existing rotation/mirror representation.
- The packaged library contains forty entries. The [approved template refresh](docs/design/builtin-template-refresh.md) updates `Resistor`/`Capacitor` artwork without changing terminals, adds `ElectrolyticCapacitor`, and supplies `OpAmp.Grid10` as the normal op-amp. The legacy `OpAmp` entry and its Compatibility category were removed with user approval on 2026-11-07; no dependent saved schematics exist. `OpAmp.Grid10` remains the standard op-amp. No alias or migration is provided. Earth (`Ground`) retains its terminal interface but now uses a compact 20/12/4-unit three-bar body at y = 0/4/8 to match the newer ground family; jack artwork is unchanged. The diode body is now 10 × 10 units, preserving its square aspect ratio and matching resistor thickness; its cathode bar spans y = -5 to 5 at x = 5. Leads meet the resized body at x = ±5 while the anode/cathode terminal positions remain (-20, 0)/(20, 0). Packaged IDs are distinct from the manually importable `Grid10.*` template IDs, so both collections can coexist through the normal registry.
- Symbols are library data, not C++. Each is a JSON entry (stable string ID, display name, category path, reference prefix, `showsReference`, primitives, named terminals). The current initial collection is under `core/symbols/`, embedded as Qt resources and listed in a nested category manifest that fixes hierarchy and palette order; this is its current packaging, not a separate symbol type. `SymbolLibrary` in `schematiccore` loads and validates entries (Qt Core only) and rejects duplicate IDs; invalidity of the current initial collection is fatal. All library sources should use the same definition and identity rules. A symbol's ID is its serialization name, and the initial seven IDs are the pre-library kind names, so earlier files load unchanged. Categories are `/`-separated paths such as `Semiconductors/Diodes` and are presentation only. Polarity and type variants are separate entries, not flags. Until the SVG authoring workflow is implemented, adding an entry to the current collection requires a data file, manifest and CMake resource updates, and a test.
- Reference labels are trimmed and must be non-empty and unique among other components. Values are trimmed, may be empty, and need not be unique. Load repair/rejection follows the explicit policy above.
- Instance properties form an ordered collection with reserved Reference and Value first, followed by custom text properties with stable IDs. Each has independent canvas visibility. V5 requires valid reserved rows and non-empty unique references; it rejects duplicate legacy reference/value fields. Custom names are unique per instance.
- The Properties dock defaults beneath Symbols on the left; saved user layouts take precedence. It edits values and visibility. Multi-selection uses mixed-value placeholders and tri-state visibility; a bulk action is atomic and one undo step. Reference text and custom-name editing require one component. Editing a partially present custom row creates missing properties without changing existing visibility. Double-click focuses Value; F2 focuses Reference. Pending text is cancelled when selection or document context changes.
- Visible non-empty Reference, Value, and custom `Name: value` rows form one compact, upright property block, automatically below transformed artwork. Dragging text moves only its block, freely in scene units. The optional instance offset is from the component origin along canvas axes; translations carry it along and rotations/flips preserve it. Text/visibility changes retain custom top-left anchors. Reset clears the offset and restores automatic placement. Hidden/empty rows consume no space, but offsets survive when all rows are hidden. Geometry, terminal interfaces, and wire topology do not depend on property placement. See the [approved block design](docs/design/property-block-placement.md).
- Component transforms are stored as quadrant rotation and local horizontal mirroring. Toolbar controls provide 90-degree left/right rotation and horizontal/vertical flips relative to the canvas axes, regardless of the current pose. Both fields change atomically for a flip, with connected routes validated only against the final pose; no format change is needed. Mirroring is applied to local symbol geometry before rotation; text labels remain readable. Transform operations update connected routes transactionally.
- Default references are the kind's prefix plus the smallest unused number (`R1`, `VR1`, `GND1`). The potentiometer prefix is `VR`. Library `showsReference` initializes instance Reference visibility (Ground starts hidden); the instance then owns that flag. Legacy loads initialize it from the resolved symbol definition. Showing a ground reference changes only that instance.
- The symbol palette separates category browsing from symbol display: a library-driven category tree above the graphical symbol grid filters its contents. A draggable horizontal divider starts at equal heights; the category tree scrolls horizontally and vertically as needed. Symbol thumbnails share the canvas renderer and use compact icon-only tiles with names in tooltips and accessible labels. Tiles wrap to fill the available palette width as the dock or splitter is resized. A fixed preview box preserves aspect ratio and caps artwork at default canvas scale, shrinking oversized symbols without enlarging smaller ones. Clicking a symbol keeps repeated click-to-place; dragging it to the canvas places one component through the undoable edit path.

- Block Schematics contains buffer and a two-input summing node; its Filters subcategory contains high-pass, low-pass, band-pass and band-stop filters plus variable versions of all four (`Block.*` IDs). Each has a centred 40 × 40 scene-unit box, 10-unit left/right leads, prefix `B`, and visible references by default. Filters and buffer have `in` at (-30, 0) and `out` at (30, 0); summing has ordered `in1` (-30, -10), `in2` (-30, 10), and `out` (30, 0). Variable filters add a diagonal arrow with a filled black head to their response curves and have no extra control terminal. These use the normal library terminal-signature and connectivity rules.

- Potentiometer and Preset Resistor share the resistor's 20 × 10 white body, 40-unit end-terminal span and a short straight arrow inside the body pointing towards terminal `2`, indicating clockwise wiper travel. Both use prefix `VR`, with ordered terminals `1` (-20, 0), `2` (20, 0), `wiper` (0, -20). Preset Resistor (`PresetResistor`) uses a crossbar at y = -9 instead of an arrowhead; the potentiometer retains its filled black wiper arrow. The existing potentiometer terminal interface is unchanged. Filled black arrowheads are the default, including variable-filter arrows.

- Semiconductor categories are `Semiconductors/Diodes`, `Semiconductors/Transistors`, and IC subcategories `Semiconductors/ICs/Op Amps`, `Semiconductors/ICs/Buffers`. The collection manifest contains the ordered nested category tree: each node has `name`, optional `symbols` filenames and optional `children`. The tree owns collection placement; definition category paths must match it. Parent symbols precede children in preorder. Empty nodes are supported, duplicate sibling names or file listings are errors, and imported symbols/collections merge through the same core tree. Legacy flat manifests remain readable and writable-library saves upgrade them transactionally. See the approved [category-tree manifest design](docs/design/category-tree-manifest.md). Categories remain library presentation metadata and are not document topology.
- Schottky Diode (`SchottkyDiode`), Zener Diode (`ZenerDiode`), and LED (`LED`) share the standard diode body and terminal layout, prefix `D`, and visible references. Schottky uses a hooked cathode bar; Zener uses a bent bar; LED adds two outward arrows with filled black heads.

- Six circle-free transistors share terminal positions and index roles: base/gate at (-20, 0), collector/drain at (10, -20), emitter/source at (10, 20) for N versions; P versions are vertically flipped by default, with collector/drain at (10, 20) and emitter/source at (10, -20). The default width is 30 units; all left bars align at x = -5, and collector/emitter and drain/source tips are vertical with no horizontal end stubs. IDs are `PNP.Compact30`, `NPN.Compact30`, `NChannelJFET.Compact30`, `PChannelJFET.Compact30`, `NChannelMOSFET.Compact30`, `PChannelMOSFET.Compact30`; the previous six palette entries are replaced, with no reuse of their IDs or aliases for the changed terminal interfaces; prefix `Q`, references visible by default, category `Semiconductors/Transistors` without subcategories. BJT arrows are on the emitter (NPN outward, PNP inward); JFET gate arrows point into the channel for N and out for P. JFET drain/source branches attach at y = ±8 on the bar spanning y = ±10, matching the MOSFET attachment levels. Exposed terminal positions remain unchanged. MOSFETs are three-terminal enhancement-mode with a broken channel, isolated gate, and body tied to source; their body arrows point into the channel for N and out for P. No enclosing circle, extra body terminal, or body-diode artwork is included.

- Powered amplifier families provide distinct with-supply and without-supply symbols, with stable IDs for each terminal interface. `OpAmp.Grid10` remains unchanged; `OpAmp.Grid10.NoSupplies` omits supply leads/terminals while preserving input/output geometry. `OTA.WithSupplies.OutputSource.VerticalBias` and `OTA.NoSupplies.OutputSource.VerticalBias` use the op-amp triangle and input terminals, place `out` at (50, 0), add `Iabc` at (30, 20), and omit linearising-diode bias. Ordered OTA terminals are `in+`, `in-`, `out`, `Iabc`, followed by `v+` (0, -20) and `v-` (0, 20) only in the supplied variant. Two unfilled circles of radius 6 centred at (26, 0) and (34, 0) represent the output current source, with no arrow. Bias artwork runs vertically from (30, 20) to their lower intersection at (30, √20), ending level with the lower supply pin. The new `.OutputSource.VerticalBias` IDs replace the earlier OTA palette entries without reusing IDs for the changed output and bias terminal interfaces. The two-terminal `DarlingtonBuffer.LM13700` is an explicit exception: `in` (-20, 0), open-emitter `out` (10, 20), internally tied collectors, no exposed supply or collector terminal and no supply variant. These IC symbols use prefix `U`, visible references, and Op Amps (including OTAs) and Buffers subcategories. No package pin numbers or implicit document nets are introduced.

- OTA Bias position is an authored layout choice, not free-text property data. Below retains the existing `.VerticalBias` IDs; Above uses `.BiasAbove` IDs with Iabc at (30, -20). Native symbol definitions carry optional `layoutControls` with stable keys, current/available choices, target IDs and explicit one-to-one terminal-name mappings. The document switches symbol ID and repairs mapped wires transactionally; pose, instance properties, label offsets and topology remain intact. The single-selection Properties dropdown uses the existing undo path; Above/Below are local to the normal pose. Format v7 embeds the reachable alternatives, and clipboard fragments preserve them. Old embedded definitions without controls are not silently upgraded. See the approved [layout-variant design](docs/design/symbol-layout-variants.md).

- Optional symbol `paletteVisible` defaults to true and is serialized only when false. It affects palette actions, tiles and derived categories, not lookup, rendering, document embedding, variant switching or connectivity; explicitly declared categories may still be empty. The two OTA Above definitions set it false, leaving one visible OTA per supply configuration with a default Below bias. Native JSON and SVG sidecar import/export preserve the flag. This is presentation metadata, with no new document-version change beyond v7.

- Signals has Power Rails, Grounds and Ports categories. `Ground` retains its terminal interface and uses compact three-bar artwork (20/12/4-unit widths at y = 0/4/8), is presented as Earth, and moves to Signals/Grounds. The palette provides one Power Rail, Chassis and unnamed Signal Ground plus Input/Output/Bidirectional ports. Signal Ground starts unnamed and can be named through Value. Power Rail retains ID `Rail.VCC` and terminal (0, 20), defaults to `Vcc`, and uses a 20-unit horizontal bar crossed by its vertical lead with a filled dot at (0, 0). Other supply names and directions use Value editing and the existing transforms. The redundant VEE/VDD/VSS/Named Rail and AGND/DGND definitions were deleted with user approval because no older drawings depend on them. All references default hidden; rail prefixes are `PWR`, grounds `GND`, ports `PORT`. Editable Value labels identify names, with no same-name net merging or hidden electrical connections. See the approved [connection-symbol design](docs/design/signal-connections.md) for frozen terminal positions and geometry.
- Optional library `defaultValue` is trimmed single-line text, default empty and omitted when empty; non-string/multiline values are rejected. It initializes the existing Value property only on new component creation. Library updates, layout switching, loading and paste preserve instance-owned values, including explicit empty values. Native JSON and SVG sidecars preserve it as presentation metadata in format v7; no version bump or extra instance state is needed. Existing movable upright property blocks display the labels.

- A single selected wire is reshaped by perpendicular segment dragging (horizontal moves vertically, vertical moves horizontally), snapped to the document grid. Consecutive collinear vertices form one straight run. The core `moveWireSegment` operation preserves wire and endpoint identities, anchors component terminals, and moves shared nodes at the ends of the dragged run. It inserts perpendicular end connectors and repairs incident routes where needed. Selection translation carries junctions incident to moving wires and repairs unselected branches. In either drag mode, a junction stays anchored when two stationary wire legs form a straight through-run. Zero-length bends and same-direction redundant vertices collapse; reversals and other invalid geometry reject the edit atomically. The scene previews from the original snapshot and release commits one undo step; Escape cancels. Selection uses a fixed screen-pixel picking tolerance and red route highlighting. Mixed/multiple selections retain group movement. Crossings never create connectivity, and no persistence-format change is needed.

- Alt+click selects a straight wire run. Ctrl+Alt+click toggles runs in that selection. Drag a highlighted run to reshape all selected runs in one undoable edit. Junctions shared by moving rail runs follow those runs, and attached branches keep their endpoint identities. Selection tracks the surviving runs after cleanup and restores with undo/redo. Delete and Cut operate on whole-object selections.

- Wire drawing uses one resolved point for hover, preview and completion. Branch targets snap along the existing route while retaining its exact (possibly off-grid) axis; snapping onto a route endpoint reuses its terminal/node identity. A trailing draft vertex already at the completion target is consumed as the endpoint rather than duplicated, allowing completion after an empty-space click has snapped onto a terminal.

## Symbol library authoring

- All symbols are entries in one library and use the same definition, validation, lookup, import/export, and document rules. Packaged and writable storage locations are distribution details, not separate symbol types; duplicate IDs are surfaced as conflicts rather than silently shadowed.
- Custom glyphs are authored in an external SVG editor and imported through the approved restricted SVG profile. The importer applies SVG element transforms, subtracts the chosen origin from artwork and terminals, and stores a self-contained native symbol definition. The profile supports fill and `nonzero`/`evenodd` fill rules; arcs and ellipses convert to cubic paths within 0.1 scene units. Individual-symbol SVG export is part of authoring; complete-schematic SVG export is a separate future capability.
- A symbol ID's immutable terminal signature is terminal count, order, names, and local positions. Any change to that signature requires a new ID. Glyph artwork and presentation metadata may change under the same ID because they do not change connectivity.
- Project format v3 embeds the full definitions of every symbol used by a document, preserving its saved appearance. Versions 1 and 2 remain loadable and resolve symbols from the current library. On conflict, GUI loading offers the choices in [the symbol authoring design](docs/design/symbol-import.md); headless loading uses the embedded definition for that document.

- Selected components use red artwork strokes, red formerly black fills, and red visible property labels; white and unfilled interiors retain their fill behavior. Component and primitive selection rectangles are suppressed. Deselection restores normal colours, including after scene rebuilds and transform previews. Wire selection highlighting and directional drag-selection boxes retain their existing behavior. This is transient scene appearance only, with no document-format or connectivity changes.

## Milestone boundaries

- Select-mode box selection uses left-to-right enclosure and right-to-left crossing, with solid blue and dashed green feedback respectively. Components include their displayed labels as one target; wires are whole-route targets using stroked geometry. Plain drag replaces selection, Ctrl-drag adds to the starting selection, and Escape restores the starting selection. Selection remains transient UI state and does not change connectivity or undo history. See the approved [group-selection design](docs/design/group-selection.md).
- Selected components and wire routes move, rotate, and flip atomically per the approved [group-transform design](docs/design/group-transforms.md). A component drag snaps its origin and applies one shared displacement; a wire drag snaps displacement. A lone component rotates/flips around its origin; other selections use their artwork/wire geometric center, excluding labels. Direct wires between selected components transform rigidly; branch nodes move only when every incident route is included. Outside endpoints remain anchored, deterministic orthogonal end repairs preserve identity, and any invalid final route rejects the whole edit. Candidate previews leave the document unchanged; Escape, focus/tool changes, and rebuilds cancel them. Selection groups and pivots are transient, with no file-format change.

- The first usable milestone focuses on schematic presentation and editing. PCB layout, circuit simulation, automatic routing, and SVG-based symbol authoring are outside this milestone; symbol authoring is planned separately. The application does not include a general-purpose artwork editor.
- Undo/redo is included in milestone 2, with its own design note covering clean/dirty state, selection restoration, and command boundaries before implementation. Wire-corner reshaping, net naming, arbitrary-angle rotation and a full symbol editor remain deferred.
- Application-layer edits use a single commit path so undo/redo, palette placement, and toolbar actions share consistent document updates. `schematiccore` remains Qt Core-only; UI undo-stack integration belongs in the application layer.
- The main window uses separate Qt toolbars for File, Tools, Edit, and View actions, plus dockable panels. Toolbars default to icon-only controls on one row, with tooltips; users can move, float, and show or hide the groups. Toolbar and dock arrangement and visibility are saved in application settings. Prefer Qt's native toolbar behavior over a custom ribbon or per-command toolbar editor.
- Undo/redo stores before/after `Document` snapshots in application-layer commands. Each successful user-intent edit is one command (including a full selection drag, multi-component deletion, group rotate/flip, or branched wire operation); rejected and no-op edits create none. Selection remains UI state and is restored by component and wire IDs, including after scene rebuilds. Mixed-selection restoration extends the initial component-only implementation.
- The undo stack's clean index is the dirty-state source. Successful Save/Save As marks the current index clean; failed or cancelled file operations do not. New and successful Open reset the history. Grid-spacing changes are individually undoable; the first version has no history-size limit. Restoring a snapshot also restores document-local ID counters, so IDs from undone edits may be reused.
- Escape cancels an in-progress wire and returns the editor to Select mode. During wire drawing, persistent markers identify component terminals and a hover cue identifies the current terminal, explicit node, or wire-segment branch site under the pointer. These cues do not alter connectivity or promise that a completed route will validate.
- Grid and terminal placement should follow the world-coordinate contract above; do not move terminals onto a grid solely to make snapping simpler.

## Edit menu and schematic clipboard

- Menu/toolbar rotate and flip controls share QActions, with canvas shortcuts R / Shift+R for right/left rotation and H / V for canvas-axis flips. The Edit menu separates history, Cut/Copy/Paste/Delete, rotations, flips, and Rename. Standard clipboard/history/delete shortcuts use Qt platform conventions. Text-field focus routes menu clipboard/delete/undo/redo operations to text and prevents transform shortcuts from consuming typed letters.
- The approved [clipboard design](docs/design/edit-menu-clipboard.md) uses a version-1 application MIME fragment containing self-contained v13 document data (with v6–v8 fragments still readable). Core extraction/insertion is Qt Core-only; system clipboard access stays in the application. Only explicitly selected routes are copied. Boundary terminals become detached nodes keyed by original endpoint identity, so shared endpoints remain joined and coincident unrelated endpoints stay separate.
- Paste validates the whole fragment, allocates fresh IDs and unique references, preserves other properties and block offsets, and rejects same-ID/different-definition symbol conflicts in the destination. It does not modify the library. Canvas Paste translates the centre of copied component origins and wire vertices to the snapped canvas pointer position, without individually resnapping geometry or property blocks. Menu Paste retains the last viewport pointer position, remapped through the current pan/zoom transform; before pointer activity it uses the visible canvas centre. Repeated pastes introduce no cascade offset. The low-level displacement-based paste API remains available.
- Copy has no document/history effect. Cut publishes the fragment before the normal deletion operation; deleting a component preserves unselected incident routes as detached endpoints. Cut/Paste are single snapshot commands with selection restoration. Undo does not restore clipboard contents. Document writers now emit v13, including reachable layout alternatives and notes.

- The approved [property-block appearance design](docs/design/property-block-appearance.md) adds a persisted application anchor grid (Appearance, default 2 units), staged OK/Cancel preferences and undoable per-instance Left/Middle/Right justification. Native/sidecar `defaultPropertyJustification` defaults to Left; rails and grounds use Middle on creation. Document v8 stores the instance choice; v1–v7 migrate to Left without changing offsets. Reset retains justification; paste preserves it.

- Format v10 persists note paragraph justification and optional box fill/outline colours as validated strings (`none`, RGB or ARGB hex), preserving the Qt Core-only model. Older documents default to Left/no fill/no outline. Icon buttons edit justification; colour buttons provide alpha and None options. Appearance survives text/geometry edits, clipboard and undo, and is shared by canvas/SVG rendering.

- The document-wide drawing style is Standard or Hand-drawn, saved in format v11 and undoable. Older documents default to Standard. Deterministic application-layer path styling preserves terminal positions, route vertices and topology; canvas and SVG share it. Text, note frames, palette previews and junction dots retain their existing rendering. Individual overrides are deferred. See [drawing styles](docs/design/drawing-styles.md).

- Format v12 adds document-wide Individual/Consistent hand-drawn variation and Single/Double strokes. Older documents default to Individual + Single. Consistent symbol artwork uses a stable symbol-ID seed; wires retain individual variation. Double strokes fill each primitive once and draw two unfilled outlines. Both settings use snapshot undo/redo, persist independently of Standard/Hand-drawn, and are shared by canvas and SVG.

- Format v13 adds drawing looseness (finite 0–3, default 1), displayed as 0–300%. Variation, strokes and looseness are edited under Preferences > Appearance for the current schematic; OK commits one undoable document edit and Cancel discards changes. The compact drawing-style selector remains on the View toolbar. Looseness scales stroke deviations on canvas and SVG without moving connection anchors.

- Schematic text font family and separate label/note sizes are application-wide Preferences > Appearance settings, persisted through QSettings without changing document data or undo history. Defaults retain 8-unit labels and 10-unit notes. A shared application-layer helper supplies canvas and SVG fonts; accepted changes refresh all open drawing windows. Installed script fonts are selectable; bundling fonts and per-object font overrides remain outside this pass.

- Initial Windows distribution uses CMake/Qt deployment plus CPack NSIS and ZIP, built separately from the development output. CMake owns release version 0.1.0. Installer upgrades retain the stable Schematic install identity; application data stays in the existing per-user locations. No file associations, auto-update, signing or public publishing are included. See [Windows packaging](docs/design/windows-packaging.md).
