# Design decisions

This file records choices that affect the document model, file compatibility, or core editing behavior. Revisit them deliberately; do not treat implementation details or unresolved questions as settled decisions.

## Document model and connectivity

- The document model is independent of Qt rendering items and input handling. `Document` is the source of truth; the scene and view render it and route user edits through its API.
- Electrical connectivity comes from endpoint identity, never coordinate coincidence. Endpoints refer to component terminals or explicit document nodes. Nets and junction positions are derived; crossings do not connect unless the user explicitly creates a branch.
- A committed wire has resolved endpoints and an orthogonal route with no collinear reversal. A diagonal pointer move gets a deterministic horizontal-first corner. Grid alignment is an editing convenience, not a validity requirement for saved routes.
- Component positions, symbol geometry, and terminal coordinates use the same world/scene units. Grid spacing affects snapping and grid-line spacing; it does not scale symbols. Terminals are not required to land on grid intersections.
- Component movement updates attached route endpoints while preserving endpoint identities and validating candidate routes before commit.
- Removing a component removes wires that can no longer resolve their terminal endpoint. Shared branch nodes remain when other routes still reference them.
- Persistent net IDs and separately serialized junction lists are not part of the version 1 format.

## File format

- Project documents use versioned JSON. Version 1 stores grid spacing, components, explicit nodes, wire vertices, and endpoint references. Nets and junctions are derived.
- On load, wire endpoint coordinates are recalculated from terminal or node identity. A stale serialized endpoint is a warning; invalid topology or route geometry rejects the whole document. The loader rejects collinear reversals rather than normalizing saved geometry.
- Symbol IDs (the `kind` property of a saved component) are part of the serialization contract. Terminal geometry also affects loading because endpoint positions are derived from the current symbol definitions, and saved wires refer to terminals by index. A released symbol's terminal count, order, names, and positions must therefore never change under the same ID; any terminal-interface change gets a new ID. Glyph artwork and presentation metadata may change under the same ID because they do not alter connectivity. A document that uses an unknown symbol ID is rejected, with an error that names the component and the ID.
- Milestone 2 adds format version 2 for horizontal mirroring; v3 embeds symbol definitions; v4 preserves black/white primitive fill colour. V5 adds ordered instance properties and visibility. V6 adds optional canvas-axis property-block offsets. The loader accepts v1–v6; v1 components are unmirrored and may not contain a `mirrored` property. V2 and later require a boolean one per component. Writers emit v6, so saving an earlier document upgrades it. Older builds reject v6 rather than silently discarding layout data. V1–v5 load with automatic block placement.
- For legacy v1–v4 documents, missing, empty, and whitespace-only references are generated from per-kind prefixes with a warning. Generation avoids collisions deterministically. Duplicate non-empty references are load errors that name both components; they are not silently renamed. References are trimmed and compared case-sensitively. Loaded values are trimmed as well.

## Symbols and labels

- Symbol fill is monochrome: no fill, opaque white, or opaque black. The existing optional `filled` flag and per-kind defaults remain; `fillColor` defaults to White and is serialized only for Black. Legacy stored filled shapes remain white. SVG imports follow explicit/inherited none/white/black and SVG's default black; exports preserve the effective colour. Canvas, palette, and import previews share brush selection. Terminal signatures and stroke styling are unchanged. See the approved [black-fill design](docs/design/black-symbol-fills.md).

- Rotation is limited to 0, 90, 180, and 270 degrees. Horizontal mirroring is out of scope for milestone 1 and in scope for milestone 2 (format v2); arbitrary-angle rotation remains out of scope. The toolbar now supports canvas-axis horizontal and vertical flips using the existing rotation/mirror representation.
- The packaged library contains nine entries. The [approved template refresh](docs/design/builtin-template-refresh.md) updates `Resistor`/`Capacitor` artwork without changing terminals, adds `ElectrolyticCapacitor`, and supplies `OpAmp.Grid10` as the normal op-amp. The old `OpAmp` retains its original geometry/terminal interface under Compatibility > Legacy Symbols. Diode, ground, potentiometer, and jack artwork is unchanged. Packaged IDs are distinct from the manually importable `Grid10.*` template IDs, so both collections can coexist through the normal registry.
- Symbols are library data, not C++. Each is a JSON entry (stable string ID, display name, category path, reference prefix, `showsReference`, primitives, named terminals). The current initial collection is under `core/symbols/`, embedded as Qt resources and listed in a manifest that fixes palette order; this is its current packaging, not a separate symbol type. `SymbolLibrary` in `schematiccore` loads and validates entries (Qt Core only) and rejects duplicate IDs; invalidity of the current initial collection is fatal. All library sources should use the same definition and identity rules. A symbol's ID is its serialization name, and the initial seven IDs are the pre-library kind names, so earlier files load unchanged. Categories are `/`-separated paths such as `Semiconductors/Diodes` and are presentation only. Polarity and type variants are separate entries, not flags. Until the SVG authoring workflow is implemented, adding an entry to the current collection requires a data file, manifest and CMake resource updates, and a test.
- Reference labels are trimmed and must be non-empty and unique among other components. Values are trimmed, may be empty, and need not be unique. Load repair/rejection follows the explicit policy above.
- Instance properties form an ordered collection with reserved Reference and Value first, followed by custom text properties with stable IDs. Each has independent canvas visibility. V5 requires valid reserved rows and non-empty unique references; it rejects duplicate legacy reference/value fields. Custom names are unique per instance.
- The Properties dock defaults beneath Symbols on the left; saved user layouts take precedence. It edits values and visibility. Multi-selection uses mixed-value placeholders and tri-state visibility; a bulk action is atomic and one undo step. Reference text and custom-name editing require one component. Editing a partially present custom row creates missing properties without changing existing visibility. Double-click focuses Value; F2 focuses Reference. Pending text is cancelled when selection or document context changes.
- Visible non-empty Reference, Value, and custom `Name: value` rows form one compact, upright property block, automatically below transformed artwork. Dragging text moves only its block, freely in scene units. The optional instance offset is from the component origin along canvas axes; translations carry it along and rotations/flips preserve it. Text/visibility changes retain custom top-left anchors. Reset clears the offset and restores automatic placement. Hidden/empty rows consume no space, but offsets survive when all rows are hidden. Geometry, terminal interfaces, and wire topology do not depend on property placement. See the [approved block design](docs/design/property-block-placement.md).
- Component transforms are stored as quadrant rotation and local horizontal mirroring. Toolbar controls provide 90-degree left/right rotation and horizontal/vertical flips relative to the canvas axes, regardless of the current pose. Both fields change atomically for a flip, with connected routes validated only against the final pose; no format change is needed. Mirroring is applied to local symbol geometry before rotation; text labels remain readable. Transform operations update connected routes transactionally.
- Default references are the kind's prefix plus the smallest unused number (`R1`, `VR1`, `GND1`). The potentiometer prefix is `VR`. Library `showsReference` initializes instance Reference visibility (Ground starts hidden); the instance then owns that flag. Legacy loads initialize it from the resolved symbol definition. Showing a ground reference changes only that instance.
- The symbol palette separates category browsing from symbol display: a library-driven category tree above the graphical symbol grid filters its contents. A draggable horizontal divider starts at equal heights; the category tree scrolls horizontally and vertically as needed. Symbol thumbnails share the canvas renderer and use compact icon-only tiles with names in tooltips and accessible labels. Tiles wrap to fill the available palette width as the dock or splitter is resized. A fixed preview box preserves aspect ratio and caps artwork at default canvas scale, shrinking oversized symbols without enlarging smaller ones. Clicking a symbol keeps repeated click-to-place; dragging it to the canvas places one component through the undoable edit path.

## Symbol library authoring

- All symbols are entries in one library and use the same definition, validation, lookup, import/export, and document rules. Packaged and writable storage locations are distribution details, not separate symbol types; duplicate IDs are surfaced as conflicts rather than silently shadowed.
- Custom glyphs are authored in an external SVG editor and imported through the approved restricted SVG profile. The importer applies SVG element transforms, subtracts the chosen origin from artwork and terminals, and stores a self-contained native symbol definition. The profile supports fill and `nonzero`/`evenodd` fill rules; arcs and ellipses convert to cubic paths within 0.1 scene units. Individual-symbol SVG export is part of authoring; complete-schematic SVG export is a separate future capability.
- A symbol ID's immutable terminal signature is terminal count, order, names, and local positions. Any change to that signature requires a new ID. Glyph artwork and presentation metadata may change under the same ID because they do not change connectivity.
- Project format v3 embeds the full definitions of every symbol used by a document, preserving its saved appearance. Versions 1 and 2 remain loadable and resolve symbols from the current library. On conflict, GUI loading offers the choices in [the symbol authoring design](docs/design/symbol-import.md); headless loading uses the embedded definition for that document.

## Milestone boundaries

- Select-mode box selection uses left-to-right enclosure and right-to-left crossing, with solid blue and dashed green feedback respectively. Components include their displayed labels as one target; wires are whole-route targets using stroked geometry. Plain drag replaces selection, Ctrl-drag adds to the starting selection, and Escape restores the starting selection. Selection remains transient UI state and does not change connectivity or undo history. See the approved [group-selection design](docs/design/group-selection.md).
- Selected components and wire routes move, rotate, and flip atomically per the approved [group-transform design](docs/design/group-transforms.md). A component drag snaps its origin and applies one shared displacement; a wire drag snaps displacement. A lone component rotates/flips around its origin; other selections use their artwork/wire geometric center, excluding labels. Direct wires between selected components transform rigidly; branch nodes move only when every incident route is included. Outside endpoints remain anchored, deterministic orthogonal end repairs preserve identity, and any invalid final route rejects the whole edit. Candidate previews leave the document unchanged; Escape, focus/tool changes, and rebuilds cancel them. Selection groups and pivots are transient, with no file-format change.

- The first usable milestone focuses on schematic presentation and editing. PCB layout, circuit simulation, automatic routing, and SVG-based symbol authoring are outside this milestone; symbol authoring is planned separately. The application does not include a general-purpose artwork editor.
- Undo/redo is included in milestone 2, with its own design note covering clean/dirty state, selection restoration, and command boundaries before implementation. Wire-corner reshaping, net naming, arbitrary-angle rotation and a full symbol editor remain deferred.
- Application-layer edits use a single commit path so undo/redo, palette placement, and toolbar actions share consistent document updates. `schematiccore` remains Qt Core-only; UI undo-stack integration belongs in the application layer.
- The main window uses separate Qt toolbars for File, Tools, Edit, and View actions, plus dockable panels. Toolbars default to icon-only controls on one row, with tooltips; users can move, float, and show or hide the groups. Toolbar and dock arrangement and visibility are saved in application settings. Prefer Qt's native toolbar behavior over a custom ribbon or per-command toolbar editor.
- Undo/redo stores before/after `Document` snapshots in application-layer commands. Each successful user-intent edit is one command (including a full selection drag, multi-component deletion, group rotate/flip, or branched wire operation); rejected and no-op edits create none. Selection remains UI state and is restored by component and wire IDs, including after scene rebuilds. Mixed-selection restoration extends the initial component-only implementation.
- The undo stack's clean index is the dirty-state source. Successful Save/Save As marks the current index clean; failed or cancelled file operations do not. New and successful Open reset the history. Grid-spacing changes are individually undoable; the first version has no history-size limit. Restoring a snapshot also restores document-local ID counters, so IDs from undone edits may be reused.
- Escape cancels an in-progress wire and returns the editor to Select mode. During wire drawing, persistent markers identify component terminals and a hover cue identifies the current terminal, explicit node, or wire-segment branch site under the pointer. These cues do not alter connectivity or promise that a completed route will validate.
- Grid and terminal placement should follow the world-coordinate contract above; do not move terminals onto a grid solely to make snapping simpler.

## Edit menu and schematic clipboard

- Menu/toolbar rotate and flip controls share QActions, with canvas shortcuts R / Shift+R for right/left rotation and H / V for canvas-axis flips. The Edit menu separates history, Cut/Copy/Paste/Delete, rotations, flips, and Rename. Standard clipboard/history/delete shortcuts use Qt platform conventions. Text-field focus routes menu clipboard/delete/undo/redo operations to text and prevents transform shortcuts from consuming typed letters.
- The approved [clipboard design](docs/design/edit-menu-clipboard.md) uses a version-1 application MIME fragment containing self-contained v6 document data. Core extraction/insertion is Qt Core-only; system clipboard access stays in the application. Only explicitly selected routes are copied. Boundary terminals become detached nodes keyed by original endpoint identity, so shared endpoints remain joined and coincident unrelated endpoints stay separate.
- Paste validates the whole fragment, allocates fresh IDs and unique references, preserves other properties and block offsets, and rejects same-ID/different-definition symbol conflicts in the destination. It does not modify the library. Repeated pastes translate the fragment by increasing multiples of current grid spacing without individually resnapping its geometry. Clipboard/document changes reset the cascade.
- Copy has no document/history effect. Cut publishes the fragment before the normal deletion operation; deleting a component also removes unselected incident routes. Cut/Paste are single snapshot commands with selection restoration. Undo does not restore clipboard contents. The document format remains v6.
